# Pre-1.0 desktop releases, updates and diagnostics

**Release policy.** Successful main-branch release builds publish an immutable GitHub prerelease named dev-<12-character commit>. Stable versions are not required during development. The release workflow compiles Java 17, runs gameplay/updater/economy tests, publishes the portable package and updater payload, then downloads the published assets again to verify their exact bytes.

**Install on Windows.** The primary review-build download is **MaleficVeil-Setup-<commit>.exe** on https://github.com/mrcalzon02/The-Malefic-Veil/releases . This is a native Windows setup program produced by JDK 17 jpackage/WiX. It installs **The Malefic Veil** for the current user, bundles its own Java runtime (no separately installed Java required), adds Windows Start Menu and desktop shortcuts, permits choosing the destination, and registers an uninstaller. The shortcut launches a dedicated, non-updated Launcher.jar, which checks for published development releases **before** starting the game. Keeping this launcher separate prevents Windows locking MaleficVeil.jar during a game update. The installer build is gated by a bundled-runtime native launch and update check, then published and SHA-256 read back from GitHub.

**Other platforms / internal payloads.** MaleficVeil-desktop-*.zip remains a portable package and can be launched with play-release.bat on Windows (Java 17+ separately required) or play-release.sh on Linux/macOS. It is NOT the intended Windows installer. MaleficVeil-<commit>.zip is the internal verified delta/full update payload, not a user installer.

**Check and update.** Launching checks the published GitHub Releases API, **including prereleases** and ignoring drafts. It selects the most recently *published* eligible dev-tagged release, compares the local version and asks permission before downloading or replacing any game files. Use play-release.bat --check to check without installing, or play-release.bat --install to approve an available upgrade without the dialog; the .sh launcher offers the same arguments. No silent stable-only /releases/latest behavior. The launcher runs the updater from a temporary copy of updater.jar so it can also replace its own installed bootstrap.

**Archive integrity and recovery.** The update checks tag/full-commit consistency, the pinned archive filename, SHA-256, asset URLs and managed-path allowlist; it also limits downloads, file counts and extracted sizes. A disk journal and backup restore the last installation after an interrupted multi-file update. The package includes MaleficVeil.jar, updater.jar, assets/game, lib/shared-psx-weather-java17-v1.jar and version.txt. Player saves and diagnostic logs are outside the managed update paths.

**Save compatibility.** As agreed for pre-1.0 development, existing saves are preserved as files but there is no guarantee an updated build can read old-world formats. The updater does not delete, rewrite or migrate saved worlds.

**Diagnostics.** logs/updater.log tracks timestamped checks, available versions, downloads, errors and recovery. logs/updater-console.log captures launcher-side update output. logs/game-console.log captures game stdout/stderr. logs/game-events.log records disk-synced startup, menu, connection, world construction and scene-ready stages, host startup/tick exceptions, and uncaught-exception stack traces. The game-events log is rotated to game-events.previous.log when it exceeds its limit. These startup breadcrumbs survive process termination without a normal shutdown, although unlogged intermediate work still cannot be reconstructed.

**Unfinished for production:** independent code signing / publisher trust (GitHub SHA-256 is an integrity check, not independent authenticity), full internet multiplayer security review, automatic save migrations and a complete hands-on Windows installer UI session test. For native setup deliveries, require the EXE asset and its published download verification in addition to the main release pipeline passing. Successful automated checks plus a downloaded GitHub Release prove release publication, not full production readiness.
